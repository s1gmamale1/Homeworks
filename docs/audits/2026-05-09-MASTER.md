## Cross-cutting themes (where 2+ agents converged)

### A. Schema + UI advertise more than the backend has

The UI accepts subjects (russian, uzbek, literature) and grades (G10-11 math) that **don't exist as prompts**. Cards lobby for content (videos, lesson plans, teacher materials) that have **no schema field or runtime support**. This is the single biggest consistency gap and bites users silently.

→ Treat any new content card as **schema-first**, **infra-first**, **content-second**. Don't build content for a runtime that can't render it.

### B. The codebase has more surface than is actually used

- `ai_plan4.py` (2.4k LOC) — unimported
- 8 game-break mechanics — only 4 referenced per subject
- 30+ ai_*.py service files — orchestrator's actual call graph is a small fraction
- 3 subject dirs registered in UI without prompts

→ **Simplification PR** could shrink the engine by ~10% with zero feature loss. Aligns with user's "simple, not over-complicated" mandate.

### C. Quality variance across subjects is huge

- `math-algebra` and `geometriya-g7-11` are dense, well-structured
- `english`, `history` are thinner and missing key prompt types
- `russian`, `uzbek`, `literature` don't exist as prompt dirs at all

→ Per-subject quality matrix should drive prioritization. PISA literacy is reading + math + science — the weakest subjects (history, english) are also the most PISA-relevant for literacy/critical-thinking dimensions.

### D. The Why → How → What pattern is the most user-facing semantic gap

The mechanic exists but the LABELING and prompt-side adoption don't match. This is a 1-day fix with outsize pedagogical impact — and it's the kind of "depth not flash" change the user explicitly wants.
